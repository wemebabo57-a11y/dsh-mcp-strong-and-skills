---
name: refactor
description: Restructure existing code while preserving observable behavior and compatibility.
---

先列出需要保留的可观察约定：公开签名、返回格式、异常、序列化字段、顺序和副作用。查找真实调用方及测试；名称相似不代表语义相同，重复代码也可能属于不同业务边界。

- 每次围绕一个目标重构，例如隔离副作用、消除重复校验或缩短状态流。优先项目惯用写法，不为了层数、设计模式或行数创建新框架。
- 移动逻辑时保留执行顺序、事务范围、资源释放和错误传播。对 API、配置或持久化结构的变化明确标为行为变更，避免混入纯重构。
- 动态访问、反射和外部消费者可能不在静态引用内；无法确认兼容性时保留适配入口，并说明依据。删除代码前验证实际可达性。
- 使用既有测试或代表性输入比较前后结果与副作用；根据风险补充契约验证。检查最终差异，移除顺手格式化与无关改动。
