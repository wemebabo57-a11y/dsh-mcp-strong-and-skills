---
name: testing
description: Add or improve tests for observable behavior, regressions, boundary conditions, and interface contracts.
---

从需求或故障推导可观察结果，再决定测试层级。纯规则用单元测试，模块间协议用集成测试，关键用户路径才使用端到端测试。沿用已有测试框架，不为低风险文字或样式微调搭建新体系。

- 期望值来自业务规则或独立样例，避免复制实现计算答案。断言结果、错误和必要副作用，不依赖私有函数、内部调用次数或偶然顺序。
- 按实际风险覆盖正常、边界与失败输入；针对权限、重复操作、异步竞态和数据格式选择相关案例，不机械扩展所有组合。
- 固定时间、随机数与外部响应，清理状态；模拟放在外部边界，避免把待验证逻辑本身替换掉。接口变更检查字段、类型与缺失值语义。
- 回归测试应能击中原缺陷。先跑相关测试和必要静态检查，通过后再按影响范围扩大；记录真实命令及失败原因，不用重试掩盖不稳定性。
