# Strong Skills 0.4.3 正式版

> 不新增常驻工具：默认仍是 6 个入口，开启 Shell 后 7 个。本版收尾 0.4.3 预览线的沙箱化与内置 Bash 重写，修复审查发现的越权、环境泄漏、同步启动绕过与 Shell 语义缺口，并继续压低常驻提示词。

0.4.3 是 0.4.3-preview.1 / preview.2 之后的正式版。工具名、参数、默认开关与配置字段不变，升级后不需要迁移 profile。重点不是增加新入口，而是让已宣称的 Shell 沙箱、64 KiB 输出、172 项 Bash 对齐与提示词预算在真实边界下站得住。

### 安全与沙箱

- **根目录不可删除**：`rm -rf /`、`rm -rf .` 以前会把项目根连同 `.git` 一起删掉并返回 0。现在递归删除会识别根操作数并拒绝，`--preserve-root` / `--no-preserve-root` 会被解析，但虚拟根 `/` 始终受保护，`--no-preserve-root` 不会解除保护；虚拟文件系统的 `mkdir`、`remove`、`rmdir`、`rename`、`copy`、`chmod` 也统一拒绝作用在根 `/`。
- **符号链接可删但不跟随**：删除或重命名指向项目外的符号链接本身是安全操作，以前因真实路径越界被拒绝。现在最终组件的链接本身可删除、可改名，目标内容仍不会被读取或改写；目录中间组件的逃逸检查保持不变。
- **沙箱模式不再被 `spawnSync` 绕过**：`command`、`exec`、`xargs`、`find -exec` 与 `awk system()` 等入口以前同步启动子进程，既不经过宿主沙箱，也无法被超时或取消。现在 `command` / `exec` 统一走异步 `execExternal`：解析路径、`prepareExternal`、管道启动、64 MiB 输出上限、超时与进程树终止。同步消费者在受限模式下返回 126，并提示改用 `command` 或 `exec`，不会静默降级为无约束执行。
- **最小环境白名单**：外部进程不再继承父进程全部 `process.env`。默认只传 `PATH`、`PATHEXT`、`SystemRoot`、`WINDIR`、`TEMP`、`HOME`、用户目录、区域设置等运行必需项；显式传入的环境仍由调用方负责。`REVIEW_SECRET` 一类的宿主变量不再经 `command node` 泄漏。
- **只读模式补漏**：`touch` 修改现有文件时间、`ln` 创建链接此前绕过只读检查；现在与 `mkdir`、`rm`、`mv`、`cp`、`chmod` 一样拒绝写入，并返回失败状态。

### Shell 语义与 coreutils

- **双引号参数模式**：${v##*/}、${v//[bc]/Y}、${v%$p} 在双引号内恢复通配模式语义，不再当作字面量静默无效；未加引号的写法保持原行为。
- **数组展开**：`"${a[@]}"` 按元素分别展开，不再把所有元素拼成一个字段；负下标 ${a[-1]} 与 ${v@Q}、${v@E}、${v@U}、${v@u}、${v@L} 可用；`local -a` 与 `declare -a` 会真正创建数组。
- **heredoc 与 glob**：heredoc 内展开 `$((...))`，转义的 `\$` 不再被二次展开；虚拟根目录的 `**` 可展开；`nullglob` / `failglob` 生效。
- **控制流与退出**：顶层 `return` 打印与 Bash 相同的诊断后继续执行后续顶层命令；语法错误退出码改为 2；`local x` 与 `declare y` 保持未设置状态，不再伪造空字符串。
- **展开细节**：`$(<file)` 读取文件并去除尾部换行；IFS 为非空白字符时保留空字段；`{01..03}` 保留补零；后缀 `++` / `--` 返回旧值，前缀返回新值。
- **coreutils**：`sed -i 1q a b` 不再截断第二个文件；`grep`、`sed` 与虚拟文件系统统一为 64 MiB 读取上限；`env` 支持赋值、`-i` 与 `-u`；`pushd` 拒绝文件；`type` 与 `command -v` 报告真实外部路径，缺失名称返回 1；`find -exec` / `-ok` 明确报告“内置 find 不支持”，不再伪装成未知谓词；注册表调用不再把程序名当操作数，`cat cat` 正常。
- **管道与无界生产者**：输出超过 64 KiB 截断后立即终止仍在写入的子进程，`yes | head` 不会一直跑到超时；管道仍是整段缓冲，没有真实 SIGPIPE，但不再无限占用内存。

### 稳定性与性能

- 流式输出在 16 KiB 边界先拼接完整缓冲再解码，避免多字节字符被截成两半；`22386` 字节的 CJK 输出不再少 3 个字符。
- 搜索缓存命中响应调用方取消信号；浏览器 `WaitGate` 修复唤醒与注册之间的丢失唤醒。
- `grep -E`、`sed`、`awk` 在执行前拒绝灾难性嵌套量词（如 `(a+)+b`）。此前 26 字符输入可让事件循环冻结约 4 秒，34 字符可达数分钟；现在返回 2 号退出码与正则错误。
- 保留 preview.2 的性能结果：输出预算裁剪约 500×，工作区搜索 4–57×，运行时配置解析 27–121×，流式尾部收集最高 447×，网页缓存命中 12–23×。

### 兼容与边界

- 工具面、默认开关、配置字段与四档预算不变；默认 6 个入口，开启 Shell 后 7 个；精简模式仍为 2 个。
- 后台 `cmd &` 仍明确拒绝，返回 1 并说明无作业控制；`find -exec` / `-ok` 明确不支持；递归 `grep` 有意跳过 `.git`；`sed` / `awk` 是常用子集，进程替换、关联数组、`select` / `coproc`、extglob、gawk 专有扩展仍未实现。
- 独立 MCP 服务没有 DSH 会话沙箱，显式 `--shell on` 时仍以当前用户权限运行；需要沙箱时使用原生插件。
- 本机 desktop profile 的依赖继续保持浮动，不要写 `#tag` 或 `#main`，这样 DSHMarket 会按默认分支 `package.json` 的版本发现更新。

### 安装与升级

桌面端在「插件 → 添加插件」使用固定版本来源，安装后完全退出并重新打开 DSH：

~~~text
github:wemebabo57-a11y/dsh-mcp-strong-and-skills#0.4.3
~~~

web profile 在终端安装：

~~~sh
dsh plugin --profile web add github:wemebabo57-a11y/dsh-mcp-strong-and-skills#0.4.3
dsh --profile web
~~~

需要 **Node.js 24.9+** 与 **DSH 0.2.1-rc.3 或同一兼容范围内的更新版本**。
