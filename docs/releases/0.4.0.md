# Strong Skills 0.4.0 正式版

> 更短的提示词、可持续按需调用的工具面，以及真正能在后台看网页的浏览器。默认 6 个工具，Shell 作为可选第 7 个入口。

0.4.0 是 0.3.1 之后的正式功能版本。它把提示词改写得更短、更直白，新增联网搜索与真实无头浏览器，提供不依赖系统 Bash 的插件内置 Bash，并为 PTC（`run_code` 里调用工具）补上专门指导。0.4.0-preview.1 中的可选多后端 Shell 继续保留。

### 本次更新

- **提示词工程重写**：通用增强、澄清策略、Pro/Flash 专用策略、深度检查、Claude 模式与 we need to 思维都改成短句和常见词，去掉重复要求与长定语；工作流、证据要求、自我审查和汇报边界保持原意。常驻提示词比 0.3.1 更容易读懂，也更少占用上下文。
- **`strong_web`：文本模型的联网入口，不启动浏览器**。`search` 返回 JSON 结果列表，包含稳定的 `id`（如 `r1`）、标题、网址、域名和摘要；模型可以挑一条，再用 `open` 按 `id` 或网址读正文、描述与前 40 条链接。使用 DuckDuckGo HTML 搜索，失败时回退 Bing；最近 10 次查询在进程内缓存 10 分钟；单页最多 2 MB、15 秒超时，错误以中文说明返回。
- **`strong_browse`：真实 Chrome/Edge，后台无窗口**。通过本机浏览器的 headless 模式与 CDP 驱动，支持 `open`、`snapshot`、`screenshot`、`click`、`type`、`press`、`scroll`、`wait`、`close`。截图写到临时目录，并作为 image 内容交给能接收图片的视觉模型；文本模型只拿到路径和提示。`auto` 只在视觉模型路由上注册，`on` 强制开启，`off` 关闭；可用 `browserPath` 指定浏览器可执行文件。每个项目一个会话，动作串行，空闲 3 分钟自动关闭。
- **插件内置 Bash，不要求电脑已安装 Bash**：Shell 后端新增 `builtin`。它是插件内的 JavaScript 实现的 POSIX 子集，支持引号、变量、`$()`、管道、`&&`、`||`、`;`、`>`、`>>`、`<`、`2>`、`1>&2` 和通配符；内置 `echo`、`cd`、`pwd`、`ls`、`cat`、`head`、`tail`、`grep`、`wc`、`mkdir`、`touch`、`rm`、`cp`、`mv`、`test`/`[`、`env`、`export`、`sleep`、`which`、`basename`、`dirname` 等常用命令；其他程序按 PATH 直接启动，不经过第二层 shell。`auto` 在 Windows 依次尝试 Git Bash → WSL → PowerShell 7 → cmd，最后落到内置 Bash；POSIX 先找 `bash`，再落到内置 Bash。其他后端与原有行为不变。
- **PTC 模式优化**：新增 PTC 指导，说明这里的工具就是代码函数、互不依赖的查询用 `Promise.all` 并行、只返回筛选后的字段、不要打印整份 JSON、浏览器用完调用 `close`、截图只在确需看页面时使用。DSH 暴露 `run_code` 时自动出现；`ptcMode` 可选 `auto`、`on`、`off`。新工具 schema 保持紧凑，结果有明确上限。
- **设置、CLI 与 MCP 全链路**：设置页新增「联网与浏览器」组（联网开关、浏览器 auto/on/off、PTC auto/on/off、浏览器路径），Shell 后端下拉加入「内置 Bash」。CLI 新增 `--web`、`--browse`、`--ptc`、`--browser-path`；MCP 将 `strong_web` 与 `strong_browse` 标记为开放世界，`strong_shell` 继续标记为非只读、可破坏。
- **工具面**：扩展模式默认注册 `strong_skill`、`strong_context`、`strong_code`、`strong_review`、`strong_web`、`strong_browse` 6 个入口；开启附加 Shell 后为 7 个。精简模式仍是 `strong_skill` + `strong_context` 2 个入口。无限模式强制扩展工具面，但不会自动开启 Shell。
- **兼容与保留**：0.3.1 的项目设定、公共/专属知识库、`knowledge`/`project` action 与 6000 字符知识预算保留；8 个按需技能、无限 token 模式、we need to、Claude 模式继续工作。运行时依赖仍为 0，客户端分发文件已提交，无需构建。

### 安装与升级

桌面端在「插件 → 添加插件」使用固定版本来源，安装后完全退出并重新打开 DSH：

```text
github:wemebabo57-a11y/dsh-mcp-strong-and-skills#0.4.0
```

web profile 在终端安装：

```sh
dsh plugin --profile web add github:wemebabo57-a11y/dsh-mcp-strong-and-skills#0.4.0
dsh --profile web
```

从 0.4.0-preview.1 升级时，重复上面的安装命令并重启同一 profile。旧配置中的 `bashTool` 会迁移到 `shellTool`，其他字段不需要手动改。

需要 **Node.js 24.9+** 与 **DSH 0.2.1-rc.3 或同一兼容范围内的更新版本**。MCP 接入不依赖 DSH，但 PTC 指导只在宿主提供 `run_code` 时自动出现。

### 验证情况

- 150 项自动化测试通过，覆盖技能路由、原生宿主契约、stdio 往返、知识库、设置/CLI/MCP 往返、Shell 后端与内置 Bash、联网搜索解析与缓存、浏览器开关、PTC 策略和工具预算。
- `node scripts/check.mjs` 通过，包含默认 6 工具 ≤1600 tokens、精简 2 工具 ≤650 tokens、附加 Shell 7 工具 ≤1900 tokens 的预算门禁，以及浏览器分发文件新鲜度检查。
- 真实无头 Edge 已打开 example.com 并生成 1280×900 PNG，截图经读图确认；真实 DuckDuckGo 搜索与正文打开已验证。开发过程中未发送模型生成请求。
- 未对真实登录态、复杂单页应用、超大页面或所有浏览器版本做穷尽验证。

### 边界

- `strong_web` 是轻量阅读器，不是完整爬虫：只取 HTML/XML/文本，不执行页面脚本，不处理登录、表单或下载；需要渲染后内容时用 `strong_browse`。
- `strong_browse` 使用临时用户目录启动本机浏览器，不继承日常浏览器的登录状态与扩展；首次使用需要本机安装 Chrome、Edge、Brave 或 Chromium，或用 `browserPath` 指定路径。macOS/Linux 的路径发现已实现但未在本次环境逐一实测。
- `strong_shell` 与内置 Bash 都以当前用户权限运行，不经过 DSH 原生沙箱或审批。内置 Bash 会限制内置命令的路径在项目内，并拒绝目录穿越；外部程序仍可访问当前用户有权访问的其他路径。仅应在可信项目中开启。
- PTC 指导是提示词层面的建议，不能保证模型一定并行或一定不打印大 JSON；实际行为取决于模型与宿主执行器。
- 浏览器截图能否直接进入模型上下文取决于当前模型路由是否声明接受图片；不接受时只返回文件路径。
