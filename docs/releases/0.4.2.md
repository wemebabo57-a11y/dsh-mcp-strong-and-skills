# Strong Skills 0.4.2 维护版

> 不新增常驻工具、不改默认预算，集中修复 Bing 跳转、Shell 超时，以及浏览器点击和截图在 PTC 下的正确性问题。默认仍是 6 个入口，附加 Shell 后 7 个。

0.4.2 是 0.4.1 之后的正确性维护版本。工具面、默认开关、配置字段与预算保持不变，修复四项会在真实使用中直接暴露的问题：Bing 搜索结果返回跳转页、`strong_shell` 超时不生效、点击不存在的元素静默“成功”，以及 PTC 下浏览器截图输出无法被宿主序列化。

### 修复

- **Bing 搜索不再返回 `bing.com/ck/a` 跳转页**：解析 Bing 结果时识别 `/ck/a`，当 `u` 参数以 `a1` 开头时按 base64url 解出真实目标，解码 HTML 实体，并只接受 http(s) 地址；无法解包时回退原链接。结果在解包后再按规范化 URL 去重，因此同一目标的不同 `p`/`ntb` 参数会合并。真实搜索已复验返回 `deepseek.com`、`github.com` 等真实域名，打开首条结果能取得正文。
- **`strong_shell` 超时真正生效**：超时或取消时终止进程树，并在 750 ms 后强制完成结果，另以子进程 `exit` 事件兜底，避免孙进程持有 stdout 时只等 `close`。原来的 `timeoutMs: 1000` 遇到 `sleep 10 & wait` 会等满约 10 秒；修复后会在 3 秒内返回。超时或取消获胜时还会销毁输出流并 unref 子进程。
- **`strong_browse click` 明确报告缺失目标**：点击元素查找失败时 DOM 谓词返回 `false`，动作层抛出 `BROWSER_TARGET_MISSING`，不再返回一个看似成功的页面状态。真实 Edge 中点击 `#nope` 已验证会报错。
- **`strong_browse screenshot` 在 PTC 下可返回**：图像块改由模块级 `WeakMap` 按工具结果传递，`execute` 返回的对象保持纯可枚举 JSON，`render` 仍会追加 image 块；不再使用导致 PTC 报 “value is not lossless JSON” 的非枚举 `_imageBlocks`。截图本身仍保存到会话临时目录，文本模型只收到路径与提示。

### 兼容与边界

- 工具面、默认开关、配置字段与预算均不变：默认 6 个入口约 1,473 tokens，附加 Shell 后 7 个入口约 1,798 tokens，精简模式与关闭增强思考的组合仍为 562 / 886 tokens。
- 这些修复不改变 `strong_shell` 的既有边界：它仍以当前用户权限运行，绕过 DSH 原生沙箱与审批，只应在可信项目中开启；进程树终止仍是尽力而为，不构成操作系统级隔离。
- 0.4.1 的 `strong_web` 缓存隔离与 SSRF 防护、非 ASCII diff 路径、浏览器生命周期、统一参数校验与输出预算等修复继续保留。

### 上下文预算

以下为 `node bin/strong.mjs budget` 的字符启发式估算，不是 tokenizer 或账单测量：

| 配置 | 常驻工具 | 估算 tokens |
| --- | ---: | ---: |
| 扩展工具 + 均衡增强（默认） | 6 | 1,473 |
| 扩展工具 + 附加 Shell | 7 | 1,798 |
| 精简工具 + 关闭增强思考 | 2 | 562 |
| 精简工具 + 附加 Shell + 关闭增强思考 | 3 | 886 |

普通模式不预载技能正文；只有 `strong_skill` 被调用时才读取。联网与浏览器工具只在模型实际调用时访问网络。

### 安装与升级

桌面端在「插件 → 添加插件」使用固定版本来源，安装后完全退出并重新打开 DSH：

```text
github:wemebabo57-a11y/dsh-mcp-strong-and-skills#0.4.2
```

web profile 在终端安装：

```sh
dsh plugin --profile web add github:wemebabo57-a11y/dsh-mcp-strong-and-skills#0.4.2
dsh --profile web
```

需要 **Node.js 24.9+** 与 **DSH 0.2.1-rc.3 或同一兼容范围内的更新版本**。
